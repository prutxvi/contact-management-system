# Measured benchmarks

Generated by `bench/bench.cpp`, compiled with `c++ -std=c++17 -O2` on clang 21.0, Apple Silicon.

Every figure is measured at run time by this program; nothing here is copied from a textbook. Re-run `make measure` to reproduce it.

## How to read these numbers

- The hash map and the trie stay flat as n grows; the linear scan grows with n.
- The ordered map is the honest baseline for prefix search, and at a few thousand
  in-memory records it beats the trie: pointer chasing through a balanced tree is not
  that different from pointer chasing through a trie, and the trie pays more per node.
  The trie still wins by a wide margin against the linear scan, and it wins outright
  when keys get long, the prefix is short, or suggestions must be ranked as the user
  types. Read the trie column against both baselines, not one.
- The sorted vector lost at every size measured here, but only by about 1.6x to 2.5x,
  not by the factor the O(log n) bound might suggest: each binary-search step touches
  contiguous memory, so it is cache friendly. It also needs no hash table at all, and
  unlike a hash map it supports range queries such as "all numbers starting 98".
  That is why the ordered name index in this project is a std::map and not a hash map.
- Indexing costs once at insert time and pays back on every later lookup.
- std::stable_sort performed about 1.9x more comparisons than std::sort and took about
  twice the wall time. That is the price of the guarantee that records sharing a key
  keep their input order; std::sort gives no such guarantee.
- Comparisons are counted through an extra increment in the comparator, which inflates
  both sorts and penalises the one that compares more often.
- Plain vector::erase is O(n) because every later element must move. Swap-with-last
  keeps the array dense while moving at most one record, so it wins as n grows and
  loses at n = 1,000 where the index repair dominates.
- Re-run on your own machine: absolute times are machine dependent, the shape of the
  curves is not.
